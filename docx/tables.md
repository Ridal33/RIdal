1.	Паспорт проекта (пара 5)
Название: «Кофейня „Зерно“» - учёт заказов и остатков.
Проблема: у небольшой кофейни заказы пишут на бумаге, а остатки ингредиентов - в блокноте: бариста путается, что есть в наличии, а владелец не видит, сколько и чего продали за день.
Пользователи:
 гость кофейни - выбирает напитки и оформляет заказ;
 бариста - принимает заказ и списывает ингредиенты со склада;
 владелец (администратор) - смотрит отчёты по продажам, управляет меню и учётными записями.
Цель: дать гостю возможность выбрать напиток и оформить заказ, а бариста - видеть актуальные остатки и списывать ингредиенты автоматически.
Метрики успеха:
 время оформления заказа бариста - < 1 минуты;
 гость находит нужный напиток через меню/фильтры - за < 3 кликов;
 остатки ингредиентов обновляются сразу после продажи, без ручного ввода;
 отчёт по продажам за день формируется автоматически к закрытию смены.
Границы (что НЕ делаем):
 реальные платёжные шлюзы не подключаем (оплата - симулятор);
 мобильного приложения нет - только веб;
 доставка не моделируется - заказ выдаётся на барной стойке;
 бухгалтерский и налоговый учёт не ведём;
 интеграции с поставщиками и складским оборудованием нет.
Риски:
 не успеем с отчётами к дедлайну → приоритизация: сначала меню и заказ, отчёты - в конце;
 сложно придумать 30+ позиций меню → берём реальный ассортимент кофеен из открытых источников;
 бариста может ошибаться при списании ингредиентов → справочник рецептур с авторасчётом расхода на порцию;
возможны расхождения в остатках → журнал операций и ручная корректировка остатков для администратора.

2.	Техническое задание v1 (пара 5–6)
2.1.	Назначение системы
Вебсистема для автоматизации учёта заказов и остатков ингредиентов в небольшой кофейне. Заменяет бумажные записи заказов и блокнот с остатками.

2.2.	Цели и задачи
Цель - из паспорта. Задачи:
вести меню напитков с рецептурами;
принимать заказы и отслеживать их статусы;
автоматически списывать ингредиенты по рецептуре;
показывать актуальные остатки на складе;
формировать отчёт по продажам за смену;
разграничивать доступ по ролям.

2.3.	Функциональные требования
Роли и права:
гость - просмотр меню, оформление заказа;
бариста - приём заказа, списание ингредиентов, просмотр остатков;
владелец (администратор) - управление меню, пользователями, отчёты.
Меню: список напитков с категориями; карточка напитка (название, цена, состав, рецептура); фильтры по категориям.
Заказ: создание заказа бариста; статусы «создан → готовится → выдан»; автоматический расчёт стоимости.
Склад и остатки: справочник ингредиентов с единицами измерения; рецептуры (расход на порцию); автосписание при выдаче заказа; ручная корректировка остатков администратором.
Отчёты: отчёт по продажам за смену (количество заказов, выручка); журнал операций по остаткам.

2.4.	Нефункциональные требования
вебинтерфейс, работает в браузере;
разграничение доступа по ролям;
время отклика интерфейса - < 2 секунд;
данные хранятся в реляционной БД.
2.5.	Ограничения - из раздела «Границы» паспорта.

5.	Модель предметной области, сценарии использования и процесс оформления заказа (пары 7–8)

5.1.	Глоссарий и модель предметной области
Напиток - позиция меню (название, цена, категория, фото, состав).
Ингредиент - складская единица с единицей измерения и остатком.
Рецептура - расход ингредиентов на одну порцию напитка.
Заказ - оформленная покупка со статусом (создан → готовится → выдан) и кодом выдачи.
Строка заказа - позиция внутри заказа (напиток + количество + цена).
Пользователь - гость, бариста или владелец (администратор) с правами по роли.

5.3.	Таблица «Сценарий оформления заказа»
№  Дорожка  Шаг процесса  Тип BPMN  Условие / результат 
1  Покупатель  Выбрать напитки в меню  Задача  Корзина наполнена 
2  Покупатель  Перейти к оформлению  Задача  Открыт экран оформления 
3  Приложение  Запросить актуальные остатки  Задача  Запрос отправлен в БД 
4  База данных  Проверить наличие и остатки  Задача  Возвращён факт: хватает / не хватает

8  База данных  Сохранить заказ, строки, статус, код  Задача  Запись в БД 
9  Приложение  Показать подтверждение с кодом  Задача  Конец: заказ оформлен 
10  Приложение  Показать «нет в наличии»  Задача  Сообщение показано 
11  Покупатель  Изменить корзину  Задача  Конец: можно повторить оформление 
BPMNпроцесс приведён на рисунке 3 (`docs/процесс_оформления_заказа.png`). Диаграмма построена в три вертикальные дорожки: Покупатель → Приложение «Зерно» → База данных.
Основная ветка (Да): покупатель выбирает напитки → переходит к оформлению → приложение запрашивает остатки → БД проверяет наличие → если всё в наличии, покупатель выбирает способ получения и подтверждает → приложение создаёт заказ и строки → БД сохраняет заказ, строки, статус и код выдачи → приложение показывает подтверждение с кодом. Конец: заказ оформлен.
Ветка «Нет»: если БД вернула нехватку, приложение показывает сообщение «нет в наличии» → покупатель меняет корзину → процесс завершается с возможностью повторить оформление.
